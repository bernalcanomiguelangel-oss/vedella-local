# Historical-failure evidence matrix (H1–H5)

Each row maps one known historical failure from the Session 8/9 brief to its root cause, the
code/constraint that fixes it, and the **real** automated tests that regress it. The
`describe`/`it` names below are copied verbatim from the cited test files.

The **After result** column reads "Covered by passing unit/integration tests; end-to-end
PostgreSQL verification pending." for every row because the Playwright end-to-end scenarios
exercise the Postgres provider and are **not** run in this environment (no Docker daemon, no
local/remote Postgres). The e2e scenario is named so it can be run once a Postgres target
(local Docker or a Neon dev branch) is available; see `docs/security-regression-plan.md`.

## End-to-end verification status (Vercel / Neon reproducibility)

The e2e scenarios above target the Postgres provider via Playwright (`playwright.config.ts`,
`e2e/global-setup.ts`). They are **Not run** in this sandbox (no Docker daemon, no Postgres).
To complete the pending After-column verification, run them against a Postgres target that
mirrors production on Vercel:

1. **Vercel + Neon (production-realistic):** point `DATABASE_URL` at a Neon **dev branch**,
   apply migrations with `prisma migrate deploy`, seed with `tsx prisma/seed.ts` (this is
   the `npm run vercel-build` path), then `npm run test:e2e`.
2. **Local Docker fallback:** a disposable Postgres container with the same migrations.

Record each run under `eval-results/` using the Evidence-location paths above; only then may
an After cell be changed from the pending wording to a PASS/FAIL result.
