# Test baseline — Vedella Local (Session 8/9 hardening, Phase 1)

> This records the **real** baseline: the exact commands run and the exact results
> observed on branch `audit/session8-9-hardening` (off `origin/main` at `bb1825e`),
> offline. **A test that was Not run is never counted as PASS.**

## Environment

- Node `>=22` (engines), npm. Network: offline — no Neon/Vercel/AI provider reachable.
- Offline DB for tests: SQLite test client generated by `pretest`
  (`prisma generate --schema prisma/schema.test.prisma` → `node_modules/.prisma-test/client`),
  loaded by `src/lib/db.ts` only when `process.env.VITEST` is set.
- The committed runtime schema (`prisma/schema.prisma`) is Postgres; the local
  git-ignored `.env` uses `DATABASE_URL="file:./dev.db"` (SQLite) and `AI_PROVIDER="mock"`.

### 5. `npm run test:e2e` (Playwright) — NOT RUN (cannot run offline)

**Listed** with `npx playwright test --list` (exit 0): **9 tests in 7 files**:

| Spec | Scenario |
| --- | --- |
| `admin-approve.spec.ts` | customer denied admin; platform_admin approves a pending product → visible; approves a machine translation → publishes |
| `browse-reserve.spec.ts` | customer browse, search, add pack + cut, reserve |
| `copy-ab.spec.ts` | copy A/B loop propose → judge → human decide with reason → history visible |
| `cycle-full.spec.ts` | reservation rejected with `CYCLE_FULL` once the cycle is drained |
| `forced-password-change.spec.ts` | temporary password forces change-password before admin access |
| `language-switch.spec.ts` | language switcher ca → es → en |
| `receipt-review.spec.ts` | receipt upload pre-fills a form; submit creates a `pending_review` record |

**Why Not run (honest reason):** Playwright's `webServer` starts `npm run dev`, which
boots the Next.js app using the **default Postgres** Prisma client. The committed schema
is `provider = postgresql` but the local `.env` `DATABASE_URL` is a **SQLite** file and no
Postgres/Neon server is reachable in this offline environment, so the dev server cannot
connect and the webServer never comes up. These 9 specs are therefore **Not run** here.

**Status: Not run ≠ PASS.** The e2e flows are reported as UNKNOWN for this baseline and
require a Postgres-backed environment (a Neon dev branch or local Postgres with
`DATABASE_URL`/`DIRECT_URL` set) to execute. This is recorded as a Phase-2 / live-env task,
not as a pass.
